# Judge Plan

## Judge Design

- Portable checks: TypeScript compiler, 31 Vitest tests, CLI and PDF-generation smoke tests
- Comparable surface: tool results, context request roles/fields, terminal behavior, provider selection, evidence analysis
- Old baseline: `packages/chapter1/context/validation/python-baseline/latest.json`
- Target evidence: generated by `context-experiment-1-1`

## Comparator Rules

- JSON key order does not affect tool-call signatures.
- Currency values use the same fixed exchange-rate table and rounding.
- Timestamps, response ids, latency and token usage are evidence, not equality fields.
- JavaScript interpreter output is not compared byte-for-byte with Python interpreter output.

## Judge Validation

- Old baseline: Python evidence reports `experiment_execution_accepted: true`.
- Repeatability: local suite passes repeatedly with no network.
- Safe negative control: a full-context follow-up missing its tool result is rejected.
- Evidence the Judge catches breakage: negative-control assertion passes.

## Cost Placement

- Per unit: TypeScript typecheck and focused Vitest tests
- Per batch: full build and full test suite
- Coordinated expensive check: real five-arm API experiment, run manually with one direct credential

## Readiness

- State: passing locally; limited for fresh target real-API evidence
- Remaining blocker: only a direct provider credential for a new live run
